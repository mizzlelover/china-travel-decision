# 通用 AI 分步旅游规划提示词

豆包或其他 AI 聊天工具的用户，可以按顺序复制以下五段到同一对话。每轮先看结果、补足关键信息，再发下一轮；不必一次贴完。方括号处换成你的情况，也可以写“不确定”。

这是一套工作要求，不会让聊天工具自动获得联网、地图或文件生成权限。工具不足时，要求它说明已经查到什么、还缺什么，以及如何继续。

## 第一轮：需求澄清

```text
请帮我规划一次中国境内旅行。先了解我的需求，暂时不要直接推荐热门目的地或排满行程。

已知信息：出发地[填写]；日期/天数[填写]；目的地[未定也可以]；同行人及需要照顾的情况[填写]；预算[填写]；想体验的事[填写]；不想碰到的事[填写]。

先复用我已说过的信息，最多问6个会实质改变方案的问题，覆盖节奏、体力、饮食、交通方式和拥挤容忍度等重要缺口。允许我回答“不确定”。将结果整理成硬约束、偏好、可调整项和未知项，等我确认再研究。
同时说明本轮实际能否联网搜索、打开网页、查地图和生成文件；没有的能力不要假装拥有。未经我明确要求，不代订、付款、取消、联系商家或发布内容。
```

## 第二轮：当期调研

```text
按刚才确认的需求开展当期调研。目的地未定时先给少量可比较候选，并解释匹配与取舍；已定时调查实际旅途需要的信息。

分开查三类信息：①官方开放、预约、交通、天气预警和临时公告；②对应出行日期、班次、房型、分店和票种的价格、供应及取消条款；③近期真实体验。注明每条关键事实的来源链接、查询时间和信息状态：已核实、估算、推断、待确认。仅有摘要或页面打不开时，准确说明核验范围，不得声称已读全文。

对评价看具体地点、体验日期、细节、同行人群、重复转载和商业线索。区分宣传热度与体验质量；负面和正面使用相同标准，不凭情绪或一条评论断言造假。公众号只有实际可访问时才能引用，不要声称能全量检索。

如果是长假，单独研究预约、检票、停车接驳、餐饮等位、酒店入住及涨价取消限制。标明往年同类假期与本次出发前信息，不用平日好评代替长假表现，不编造尚未发生的游后评价。

若没有联网能力：请只处理我提供的资料和需求分析，不给虚假的最新推荐。列出需要我提供的官方页面/预订结果、查询日期和具体条件。不要只说“出发前再确认”；说明缺口影响哪项决定、下一步查什么及查不到如何缩减方案。
```

## 第三轮：路线与备选

```text
根据已确认的目的地和证据，生成接得上的逐日行程。按出发、抵达、入住、每天移动/游玩/每餐/休息、取行李、返程组织。每段写出起终点全名、方式、上/下车点、门到门时间及其性质、缓冲、步行/台阶和休息条件。不要用“打车前往”代替路线说明。

给具名候选，不能只写“附近酒店”“当地美食”：
住宿通常比较2–3家，含地址、确切日期、人数/房间数/床型、总价和房态核验状态、取消规则、到车站与主要地点的交通，以及与同行人有关的设施证据。
餐饮按每天实际片区给主选和可接续备选，含具体分店、地址、菜品/可替换菜、价位依据、营业、排队/订位、近期口碑及适配理由。早餐也要有安排。
景点与活动写出名称/运营方、开放或场次、时长、体力限制、费用、预约和可查的余位。

无法核查动态信息时仍可保留稳定信息有依据的候选，但明确状态、核价/询问渠道、最迟何时行动、失败后如何替换。不要虚构“可订”“已预约”或设施。缺少可靠候选时直接说清缺口，不用无证据的名字补齐列表。

为本次适用的下雨、闭馆/售罄、排队过长、交通延误、疲劳制定分支：触发条件、立刻做什么、去哪个具体替代地点、怎么去、预约/费用影响、如何接回主路线。汇总预算并区分报价、参考价和估算。最后逐段检查是否能从出发站走到住处、完成用餐与活动并按时返程，修补实际缺口。
```

## 第四轮：离线手册

```text
请把已形成的完整行程制作成一份手机旅行操作手册，交付单个HTML文件。不要只复制一张日程表：用户应能在现场知道下一步去哪、怎么到、到店吃什么、预约/入住要做什么，以及变化后怎么换路线。

用手机竖屏单列布局，提供日期/阶段切换、可展开地点卡、主选与备选切换、准备/预订待办；选中方案后显示地址和后续路线。把完整名称、地址、入口/上下车点、时间性质、步行强度、休息点、来源及核验时间、状态和下一步动作直接放进页面。已订/已购只使用我确认的信息。

HTML、CSS、JavaScript和数据全部内嵌。核心内容不依赖脚本才能显示，不用CDN、网络字体、远程图片、地图瓦片、API或fetch加载行程，不要求账号、本地服务器或安装。地图/购票/订位外链逐项注明需要联网；拨号注明需要移动信号。没有网络仍能读文字地址和行动步骤，不能宣称有离线实时导航。

待办可尝试保存在本机并提供清空方式；保存失败时不影响阅读，不写入证件或付款信息。复制地址失败时保留可手动选取的完整文字。

能生成附件就提供HTML文件；不能生成附件就输出完整、未截断源码和保存为.html的步骤，不要只给伪代码。若有长度限制，先说明并按有明确顺序的连续片段输出，确保我能合并为完整文件。

请实际检查你有能力检查的部分：手机宽度布局、日期/方案切换、待办、真实断网重新打开；按抵达酒店、找到下一餐、雨天改线、疲劳休息和按时返程做任务走查。没有浏览器或断网能力就如实写未验证，并给我可自行操作的检查步骤，不能声称已通过。
```

## 第五轮：出发前复核

```text
现在请按我的实际出发日期重新复核这份行程。重新查天气预警、交通和临时管制、景点开放、预约、住宿房态/条款、餐馆营业及价格变化。把查询时间写清楚；区分我已订项目、当前查询快照与仍待确认项目。

先给变化清单：原安排、最新证据、对行程的影响、我何时从哪个渠道完成什么动作。无法联网时明确本轮没有更新事实，列出我需要补充的材料，不把旧数据改标成最新。

根据变化重排必要路段和备选，检查餐饮、休息、行李和返程仍能衔接。将更新后的HTML另存带日期/版本的新文件，保留旧版，页面显示最后复核时间。再次报告实际完成和未完成的检查。若还不能执行，指出具体缺口与临时方案，不用一句“以现场为准”收尾。
```
