# 安装与使用

先选使用方式：Codex 用户安装 `skills/` 下的版本；WorkBuddy 用户使用 WorkBuddy 专用 ZIP；豆包等普通聊天入口直接使用[五轮提示词](../prompts/通用AI_分步旅游规划提示词.md)。两种 ZIP 都以 `china-travel-decision/` 为内部顶层目录，但元数据格式不同，不要混用。

## 在 Codex 中使用

推荐让 Codex 的安装器处理：

```text
请使用 $skill-installer，从 GitHub 仓库 mizzlelover/china-travel-decision
安装 skills/china-travel-decision 目录中的 Skill。
```

手动安装时，下载仓库或 [`codex-china-travel-decision-v1.0.2.zip`](../dist/codex-china-travel-decision-v1.0.2.zip)，将技能目录放入 `~/.agents/skills/`。安装结果应为：

```text
~/.agents/skills/china-travel-decision/
  SKILL.md
  references/
    research-and-review.md
    offline-itinerary-html.md
```

仓库源码的目标目录是 `skills/china-travel-decision/`，不要把整个仓库当成一个 Skill 安装。已有同名目录时先比较版本，备份需要保留的改动；不要直接覆盖。

当前 Codex 文档采用 `~/.agents/skills/`，也支持指向 Skill 文件夹的软链接。若你使用的旧版本明确采用 `~/.codex/skills/`，依该版本说明选择一处安装，避免两处出现同名副本。技能变更通常会自动探测；未出现时可以重启 Codex 后再试。[官方技能文档](https://learn.chatgpt.com/docs/build-skills)

在对话中输入：

```text
请使用 $china-travel-decision。
我想规划一次中国境内旅行，目的地还没定。
请先了解我的日期、出发地、同行人、预算、兴趣和体力，再开始当期调研。
最后交付逐日路线、具名吃住候选、变化时的备选，以及手机离线 HTML 手册。
```

如果想自行确认加载情况，请让 AI 说明本轮是否已经读取本 Skill 及两份参考文件，并确认它实际能否联网、读取网页和生成文件。只看到技能名称不等于已经完成目的地研究。

## 在 WorkBuddy 中使用

下载 [`workbuddy-china-travel-decision-v1.0.2.zip`](../dist/workbuddy-china-travel-decision-v1.0.2.zip)。该包保留 WorkBuddy 原格式的 `display_name`、多语言描述、顶层 `version`/`author` 和参考引用。

在你当前版本实际提供的 Skill 导入入口中选择此包，并按界面要求填写信息。若没有导入入口，请先查看该版本的帮助或使用通用提示词；不要将普通聊天附件上传误认为已安装。仓库不提供平台审核或上架状态承诺，发行包也不会自动完成提交。

导入后，以一段虚构旅行需求试用，确认它会先访谈需求，再研究并说明工具边界。具体平台接受的字段与提交要求，以当前界面为准；本仓库的包结构检查不等于平台导入验收。

## 按五轮完成一次规划

1. **需求澄清：** 把日期、出发地、同行人、预算、体力、兴趣和不能接受的事讲清楚。目的地未定也可以开始。
2. **当期调研：** 让 AI 核查官方运营信息、指定日期供应与近期体验，区分已核实、估算、推断和待确认。
3. **路线与备选：** 选定目的地后，把每段交通、每餐、住宿和活动接起来，补上排队、闭馆、雨天与疲劳分支。
4. **离线手册：** 输出单个 HTML 文件，在手机上查看日期、地点卡、待办及备选；核心文字不依赖联网。
5. **出发前复核：** 重新查询动态事项，把变更写进新版本文件，并清楚标记日期。

如果当前 AI 不能联网，可以先做第一轮和资料整理，但价格、房态、开放与预约状态必须留下待核实项。要求 AI 提供准确的查询对象和操作步骤，你补充材料后再推进。不能生成附件时，让它提供完整 HTML 源码，用纯文本编辑器保存为 `.html`；不要保存成 `.html.txt`。不同手机打开本地网页的方式不同，优先使用能执行本地 HTML 的浏览器或文件查看工具；聊天应用的预览可能只显示静态内容。

## 收到 HTML 后怎么检查

先在手机上找到“抵达后第一步”和“今天下一站”；打开餐馆、酒店卡，检查能否直接读到完整名称、地址、入口和必要行动。切换雨天或疲劳方案，看替代路线是否能接回当天安排。

随后断开网络，重新打开本地文件，检查保存的行程、地点卡、方案切换和待办。页面若提示本机保存失败，查看内容仍应可用；勾选状态是否能保留取决于浏览器对本地文件的支持。地图、购票、订位与电话应注明联网或移动信号要求。

让 AI 如实报告它实际完成了哪些检查。未做真实手机或断网检查时，应写“未验证”，不能把静态结构合格说成现场体验已经通过。

## 重新生成发行包

需要 Python 3.8 或以上，无第三方依赖。在仓库根目录运行：

```sh
python3 scripts/package_release.py
```

脚本从 Codex 版元数据读取版本和作者，校验两版一致后生成 `dist/` 中两个 ZIP 及 `SHA256SUMS.txt`。每个 ZIP 仅包含 `SKILL.md` 与两份参考文件；不会打入示例、封面、证据目录或私人路径。再次运行会更新同版本的发行文件；相同源文件在相同 Python/zlib 环境下应得到相同 ZIP 内容。
